## 一个管理员身份

页面只显示“管理员”，不要求用户区分实例管理员、平台管理员和项目管理员。后台可以兼容已有权限记录，但有效管理员应能进入平台配置并执行全部岗位业务操作，无需再勾选兼任。

管理员代做操作时，操作人、姓名和审计记录均使用管理员本人；不冒充技术员、测试员或原负责人，也不因代操作自动改写任务负责人。账号停用、有效项目访问范围、记录状态和必需证据仍统一检查。

项目成员层的原生权限值不自动等于全平台管理员。项目经理不能通过设置项目岗位给普通账号授予全平台权限。原有明确管理员身份兼容保留，早期初始化误生成的管理员标记应按来源校正，不能无依据扩大权限。

## 数据管理平台角色互认

身份以可信数据平台返回的账号ID、角色和项目授权为依据，同名账号不合并，浏览器自行传入的角色不作为权限证明。

| 数据管理平台                                         | 项目平台                                         |
| ---------------------------------------------------- | ------------------------------------------------ |
| Admin／管理员                                        | 管理员                                           |
| Manager／数据经理                                    | 项目经理                                         |
| Collector／数采员                                    | 数采员                                           |
| TeamLeader／组长、Annotator／标注员、Auditor／审核员 | 首次登录统一为数采员；后续由管理员在当前平台调整 |
| Pending／待分配用户                                  | 可登录账号安全页，不自动取得项目权限             |

首次角色映射只执行一次。管理员随后在当前平台调整为项目经理、技术员、测试员等岗位后，再次登录保留当前岗位，不由默认映射覆盖。调整不回写数据管理平台。数据平台当前未提供独立的技术员或测试员全局角色，这两类岗位可由管理员按项目分配。角色变更、账号停用和项目撤权须重新核验，不让旧会话继续保留已撤销权限。

“采集员”和“数采员”已确认是同一岗位，页面统一叫“数采员”。

本轮最新要求：测试员负责完整测试业务，包括用例、套件、计划与执行；项目层面的最终验收及发布仍由项目经理或管理员负责。管理员拥有全部岗位能力，可以提交给自己处理、审核本人参与的方案、确认和关闭本人事项，不要求第二名管理员。普通岗位仍遵守各自职责及原审核限制。操作人和审计始终为实际账号，不冒用他人身份。两项均已有定向和真实HTTP验证，页面及最终运行版本另行核对；旧“测试员不可维护”和“管理员自审403”已作废。

# 角色权限与操作入口

本表按当前独立项目管理平台实现整理。业务职责支持多选、权限取并集；平台管理员自动包含全部业务职责，无需再勾项目经理、技术员、测试员。后端 `is_administrator` 是统一管理员身份依据；前端隐藏按钮不能代替接口鉴权。

## 范围与账号

- 管理员在“设置 → 成员与权限 → 全部人员”创建本平台账号、授予/取消管理员身份，管理人员工作区和项目的访问范围。
- 普通角色仅访问获授权的工作区和项目。工作区岗位适用于该工作区当前及后续新增项目。
- 管理员自动管理全部工作区及项目，无需逐个加入；已有和未来新建的范围均自动覆盖。系统保存原有访问状态，取消管理员时撤回自动权限并恢复原访问。管理员在任期间范围勾选只读，如需限制范围须先取消管理员。
- 归档、锁定、记录版本冲突、完整性校验、最后一名管理员保护等业务约束仍适用。管理员不能通过伪造工作区 URL 修改别的项目，也不会获得他人私有文档。
- 数据平台账号不建立本平台会话。DAQ 反馈身份与平台本地账号分离：采集员用户名仅作反馈署名；DAQ 服务账号不能网页登录或读取平台内部诊断和知识资料。

## 业务权限矩阵

普通角色的“允许”均以具备对应项目的有效可写访问为前提；管理员自动获得全部范围的管理访问；访客只读。项目未启用业务权限策略时保留原成员规则，新建项目默认初始化职责策略。

## 操作入口对照

| 入口                                    | 可操作人员                     | 主要操作与边界                                                                                     |
| --------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------- |
| 设置 → 成员与权限                       | 管理员；项目经理管理本项目岗位 | 普通成员可查看已授权范围内成员；不显示无效的“编辑权限”入口。跨工作区访问与管理员授权仅管理员处理。 |
| 设置 → DAQ 项目授权                     | 管理员                         | 开/关项目反馈授权；关闭或归档项目立即从 DAQ 选择项中移除，直接接口上报同样受限。                   |
| 设置 → 模型配置                         | 管理员                         | 按工作区统一配置，工作区项目共享。                                                                 |
| 设置 → 平台连接                         | 管理员                         | 保留当前支持的独立服务连接；拒绝数据平台账号/目录互认配置。                                        |
| 设置 → 报告通知                         | 管理员、项目经理               | 配置本项目报告接收；普通成员不可修改。                                                             |
| 其他配置 → 事件通知接口                 | 管理员/原生工作区管理权限人员  | Webhook 配置与密钥管理。有效管理员即使原生成员级别为15也可操作。                                   |
| 项目配置 → 状态、标签、估点             | 管理员/该范围原生管理权限人员  | 页面按钮、普通 API 和个人 API Key 接口统一限制；普通业务成员和访客不可写。                         |
| 缺陷 → 概况/诊断/处理方案/回归/操作记录 | 按业务矩阵                     | 写操作均由服务端再次检查权限、归属和版本；不通过标题或采集员署名授予权限。                         |

## 升级与回退

此轮新增 `quality.0047_administrator_access_grant`，由常规部署迁移创建权限恢复记录表。升级保留原有访问状态，管理员访问时自动补齐新范围。

若需要回退到不支持全局管理员的旧代码，应先停止本轮服务的业务请求并备份数据库，再使用**本轮代码**执行 `python manage.py migrate quality 0046_solution_contributor_ids`，确认自动访问恢复后切换旧包；重新升级再执行常规迁移。不能仅切换旧代码而忽略权限投影。该逆迁移已在隔离数据库实际验证回退和重新应用；生产执行仍应走发布/回退流程。

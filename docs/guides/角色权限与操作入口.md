# 角色权限与操作入口

本表按当前独立项目管理平台实现整理。业务职责支持多选、权限取并集；平台管理员自动包含全部业务职责，无需再勾项目经理、技术员、测试员。后端 `is_administrator` 是统一管理员身份依据；前端隐藏按钮不能代替接口鉴权。

## 范围与账号

- 管理员在“设置 → 成员与权限 → 账号管理”创建本平台账号、授予/取消管理员身份，管理人员工作区和项目的访问范围。
- 普通角色仅访问获授权的工作区和项目。工作区岗位适用于该工作区当前及后续新增项目。
- 管理员自动管理全部工作区及项目，无需逐个加入；已有和未来新建的范围均自动覆盖。系统保存原有访问状态，取消管理员时撤回自动权限并恢复原访问。管理员在任期间范围勾选只读，如需限制范围须先取消管理员。
- 归档、锁定、记录版本冲突、完整性校验、最后一名管理员保护等业务约束仍适用。管理员不能通过伪造工作区 URL 修改别的项目，也不会获得他人私有文档。
- 数据平台账号不建立本平台会话。DAQ 反馈身份与平台本地账号分离：采集员用户名仅作反馈署名；DAQ 服务账号不能网页登录或读取平台内部诊断和知识资料。

## 成员分配与缺陷验证

“账号管理”只维护登录账号和管理员身份。“工作空间成员”和“项目成员”只列出已经分配的普通账号及范围，编辑时选择新增或退出；管理员无需逐项加入。

创建账号可暂不授权、按工作区授权或按指定项目授权。工作区授权覆盖当前及以后新建的项目，项目授权仅建立必要的工作区入口，不允许自行加入其他公开项目。账号创建及授权在同一事务完成；创建后刷新失败仅重试刷新，不重复创建。

取消独立 `REPORTER` 岗位。可参与当前项目的普通成员均可创建缺陷、补充自己的问题和现场材料；只读、停用、未加入和归档项目仍不能写入。岗位保留项目经理、技术员、测试员；管理员包含全部业务职责。

缺陷“回归测试”直接安排人工步骤或多条用例。用例库保存定义及版本，实测结果归属于缺陷、修复版本、验证轮次和用例快照。同一用例用于不同缺陷，结果不共用。测试员只记录一次，缺陷页和“测试结果 → 缺陷验证”自动汇总。经理或管理员最终验收、退回补测/修复、填写原因后重开；旧轮次证据保留。

## 升级与回退

全局管理员功能新增 `quality.0047_administrator_access_grant`，由常规部署迁移创建权限恢复记录表。升级保留原有访问状态，管理员访问时自动补齐新范围。

若需要回退到不支持全局管理员的旧代码，应先停止本轮服务的业务请求并备份数据库，再使用**本轮代码**执行 `python manage.py migrate quality 0046_solution_contributor_ids`，确认自动访问恢复后切换旧包；重新升级再执行常规迁移。不能仅切换旧代码而忽略权限投影。该逆迁移已在隔离数据库实际验证回退和重新应用；生产执行仍应走发布/回退流程。

当前成员/验证功能新增 `db.0126_workspacemember_has_workspace_access`、`quality.0048_defect_verification` 和 `quality.0049_remove_reporter_duty`。0049仅清理旧岗位分配，不删除用户、缺陷、附件或审计。升级前必须备份数据库；若回退旧功能，应恢复升级前数据库和匹配代码，避免旧代码无法理解已清理岗位或新验证轮次。

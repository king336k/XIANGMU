# 远程诊断与现场处理

## 链路与职责

浏览器通过项目平台公网入口访问。采集电脑主动向平台交换短期命令与结果，不需要公网直接 SSH 到现场。机器人由采集电脑访问；它不作为另一张采集电脑卡片登记。

PydanticAI 是唯一诊断决策者；LangGraph 编排诊断与证据检查；ROSA、RAI 和 Holmes 只读取证。现场执行端运行于普通操作用户，承担真正的命令、文件修改和复测。模型密钥留在项目平台。专业工具统一串行进入同一现场执行端。

知识使用顺序是当前现场取证、项目已发布知识及有权限历史案例，然后按明确缺口查询批准的 Git/官方文档来源。历史成功与失败结果只是参考，不能替代当前版本与设备的复测。私有 Git 的项目、仓库、分支、CIDR 和只读凭据必须在中央配置，参见 ../../services/diagnostic-integrations/research.md。

## 页面

- 主导航“统计报表”下方为“远程诊断”。采集电脑按实际操作系统用户名和IP展示，持久UUID是设备主键。
- 选择电脑后可打开独立 PTY、浏览现场文件或关联反馈。
- 机器人文件通过当前 DAQ 运行连接访问，沿用 launcher 的机器人 IP 与 SSH 身份；未建立连接时拒绝访问，不使用输入框的草稿地址。
- 文件夹下载为 tar.gz。单次文件传输上限 256 MiB；上传先选本机文件，再选电脑/机器人与目录，显示完整目标并确认。
- 同名文件不覆盖，可以修改目标文件名。压缩包不自动解压或执行。上传与已部署是不同状态。
- 反馈只显示签名来源匹配安装实例或管理员明确绑定的数据。支持编号/关键字、状态、分页和历史处理轮次。
- 原缺陷“诊断”页中旧报告默认折叠，下面 Agent 现场处理展示最新结果。操作记录包含排查、修复、复测及关联上传记录。
- 重新诊断与重新验证由服务器强制只读；诊断并自动修复仍受设备工具及文件白名单限制。

## 并发与证据

同一采集电脑最多保留20个待处理任务，同一反馈不会重复入队。不同反馈按创建顺序等待，空闲后由现有 Celery 自动执行，不增加负责调度的模型。已打开终端或已有上传可以继续完成，Agent 保持等待；新终端、新上传在已有任务时提示稍后操作。Agent 执行期间，文件浏览/传输提示处理完成后重试，避免抢占执行槽。

状态接口的 queue.position 是本采集电脑前方的排队任务数，0不表示立即运行；reason 区分等待终端关闭、文件传输完成、采集电脑空闲或处理资源；stage 来自真实现场命令。页面不预测完成时间。任务等待上限30分钟，开始执行后上限8分钟；过期不盲目重放修复。Celery 释放等待任务的工作槽，不阻塞其他采集电脑。现场完整任务使用独立 field-repairs 队列，默认4个工作位、prefetch=1；普通诊断报告保留独立 diagnostics 队列与2个工作位。诊断、支持范围内的修复、复测和原反馈回写属于同一RemoteAgentRun.id，仅入队一次，不在阶段间另排修复队列。

现场执行器单次只接收一个文件/工具任务，终端输入作为独立传输。数据库只锁本设备/本任务，避免多个采集电脑连带锁住同一个项目行。

修改前校验当前内容 SHA256，保留备份；只有实际修改和对应真实复测均成功才标记已修复。只读验证成功显示“验证通过”，不声称做了修复。执行超时或无结果时不重复盲目执行修改。电脑身份/boot/权限变化后旧任务结果失效。

## 部署

数据库迁移 0057–0064。API/diagnostic-worker 使用同一版本 ProjectServer；worker 必须有固定 PydanticAI 和 LangGraph 依赖，Holmes 通过无公开端口的独立服务接入。ROSA/RAI 使用隔离的 Humble/CycloneDDS 容器，不能以标准 topic 可见替代机器人现场验证。

新安装在DAQ正常启动时安装用户服务，DAQ成功登录后私有授权marker触发自动接入；用户无需手工编辑token/config。平台部署须预先配置 `QUALITY_REMOTE_AUTO_ENROLLMENT`（enabled、project_id、owner_user_id），它允许新安装独立claim自登记，反馈密钥不具备该权限；登记服务端不会把DAQ反馈票据视为登录证明。

设备ID和claim位于用户配置目录；IP/用户名/DAQ版本不参与设备主键。原人工登记保持同一ID，OTA更新执行器但不改凭据。克隆若连machine-id一并复制，仅软件指纹不足以可靠区分，制镜需重置机器身份。机器人连接revision变更会关闭旧机器人会话、使Agent/文件票据失效，不新建采集电脑卡片。

新设备默认固定只读连接/服务取证；不能把该验证称为原业务缺陷恢复。机器人终端必须有DAQ活动连接且真实SSH健康检查通过，用户名/IP仅从后端状态取得，浏览器不能指定任意主机。

现场连接器位于 services/field-remote。DAQ 随包携带同一份执行端代码及 provenance 校验，管理入口为 scripts/remote-diagnostics/manage.sh。私有现场配置与 token 不进入 Git 或部署包。正常生产使用 HTTPS；当前指定公网 HTTP 环境仅用于用户授权模拟验收。

## 验收范围

195 是采集电脑；177 是隔离模拟机器人。Domain173 专用模拟 topic、独立配置/服务和证据目录不涉及真实电机指令。模拟通过不能推断真实机器人硬件、标定、安全链路及完整业务采集任务已经验收。

复用 DAQ 当前连接的文件路径需在真实型号机器人上另行验收；测试中使用显式登记的固定177模拟连接。项目知识审核发布继续沿用现有治理流程，历史案例不会自动变成已发布知识。

## 混合压测

组件测试：`python services/field-remote/stress_harness.py --help`。中央真实HTTP测试：`python services/field-remote/platform_stress.py --manifest - --output <新artifact.json>`；测试fixture仅通过stdin内存输入，报告不记录令牌、Cookie或请求体。先验证隔离HTTP响应标记才允许任何写入。

`plane/tests/contract/app/test_remote_mixed_load.py` 默认跳过，仅在配置专用 `REMOTE_STRESS_BROKER` 后启用。必须使用独立 PostgreSQL 测试数据库、专用Redis及具备普通UID/Bash/`/usr/bin/python3`的Linux镜像。环境变量 `REMOTE_STRESS_STATIONS` 每次为4、8或16，**每档单独pytest进程并重建其独立测试库**，避免嵌入式Celery线程生命周期跨档污染。测试镜像挂载 `/code` 为ProjectServer，`/repo` 为仓库，只读源码以外的测试数据写入 Documents/tmp/artifacts。镜像、DB URL与Cookie/令牌由运行器动态注入，禁止写入报告。

Bulk使用明确标识 controlled_stub 的固定模型替身，但HTTP、签名反馈、PostgreSQL、Redis/Celery、独立采集进程、PTY、文件原子修改与校验均真实执行。不同站点错开终端/传输/修复阶段，并计算真实工具执行与文件HTTP的时间交集；模型响应速度、真实机器人运动、多物理机容量不属于该测试结论。真实模型和195至177现场链路另做单次验收，不能与受控模型结果混报。

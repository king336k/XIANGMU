# 旧连接覆盖新执行端状态

025 更新至 DAQ `38228e9` 后，TD-D-500、TD-D-501 均能上报，但终端偶发关闭，现场任务报“连接身份已变化”。反馈绑定、设备 ID、接入来源、凭据与权限均匹配，现场只有一个稳定运行的执行进程。

平台实测在同一系统启动、同一执行进程期间，`executor_instance` 短暂从当前值变为缺失，机器人状态同时变成未连接，随后被新心跳恢复。问题不能归因于网络切换或用户安装了旧 DAQ。

## 原因与修复

站点 WebSocket 的命令推送循环缓存了最近设备身份。连接重叠时，旧连接将旧身份带入 `RemoteExchange`，本来只应领取命令的服务器轮询被当成新设备心跳，覆盖状态并触发执行端重启保护。

两个隔离 ASGI/真实数据库测试复现：新终端被关闭、新 Agent 任务被中止。修复如下：

- 服务器领取命令与设备主动上报分开；领取命令不更新时间、设备能力或身份。
- 连接握手保存当前身份，首次及后续消息、命令推送均在设备行锁内核对执行端、系统启动、用户名及主机名；过期连接被拒绝，不能替换新观察值或消费其命令。
- 同一执行端的正常重连可继续，不因握手期间收到相同执行端心跳而误拒绝。
- 旧消息确认有效前不进入快速输出缓存；凭据校验、真实重启、机器人切换、目标校验和撤权逻辑保留。
- 服务器内部标记只作为内部请求属性传递，客户端 JSON/HTTP 标头不能开启该模式；平台轮询也不能使离线设备继续显示在线。

## 覆盖范围

[新增回归](../../ProjectServer/plane/tests/contract/app/test_station_stale_push.py)覆盖旧推送覆盖新状态/中止任务、机器人新状态不回滚、旧首帧及后续消息、离线不被续命、同执行端重连重叠、HTTP 请求不能冒充内部轮询。使用独立 PostgreSQL 15.7、Redis 8 和 Python 3.12/Django 5.2 测试容器，与生产数据隔离。

这是平台接入修复，DAQ 包内容不变。现场 025 正在运行，本轮只读检查，不重启或改写 DAQ、机器人或系统服务。隔离回归通过不等同于真实机器人复位恢复；TD-D-500 的原始 00043 故障也不能仅凭终端恢复认定已修复。

# 5090主机项目管理平台部署说明

本文仅适用于10.10.10.4上的EngramProject（公网18886），不接管同机5090数据网页或18443交付平台。其他服务器、磁盘或新安装须重新检查容量、挂载、资源和网络，不能直接套用本文路径。

## 固定入口和存储布局

| 内容                               | 当前环境路径                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------- |
| 公网                               | `http://180.153.172.19:18886/`，FRP转发本机8886                                 |
| SSH                                | `engram@10.10.10.4:2222`                                                        |
| 专用rootless Docker                | `/mnt/sdh/engramproject-isolated/docker`                                        |
| PostgreSQL                         | 原卷`engramproject_pgdata`，在上述Docker目录内；升级不新建或清空                |
| 代码、网页及模型                   | `/mnt/sda/engramproject/platform/releases/`、`platform/shared/models/`          |
| Compose和配置                      | `/mnt/sda/engramproject/deployment/compose.json`、`config/`、`platform/shared/` |
| 部署包                             | `/mnt/sda/engramproject/packages/`                                              |
| 数据库/文件/配置备份               | `/mnt/sda/engramproject/backups/`，历史备份在`data/backups/`                    |
| 附件、对象存储、媒体文件、应用日志 | `/mnt/sda/engramproject/data/volumes/`                                          |
| 运维日志归档                       | `/mnt/sda/engramproject/backups/`及`platform/shared/logs/`                      |

`/mnt/sda`为本次确认剩余空间最大的机械盘。Docker短期容器日志仍在SSD的数据目录，按20MiB×5份轮转；业务日志和导出归档在机械盘。代码通常只随发布增长，附件、日志、备份和历史包会随使用持续增长。没有自动删除用户附件、旧版本或备份的规则。

## 资源

项目整体使用独立`engramproject.slice`，上限300,000,000,000字节（300 GB）、112个逻辑核（CPUQuota=11200%），不预分配或锁住这些资源。服务按实际负载消耗，容器另设合理上限；现场完整诊断修复并发仍为4，普通诊断2，不能把CPU核数当模型任务并发。所有服务（包括Holmes）必须加入同一资源组。

## 查看、启动、停止

仅使用本项目Docker socket，禁止用系统Docker误接其他服务：

```bash
export DOCKER_HOST=unix:///run/user/1000/engramproject-docker.sock
docker compose -p engramproject -f /mnt/sda/engramproject/deployment/compose.json ps
systemctl --user status engramproject-docker.service engramproject-platform.service engramproject-public.service
systemctl --user show engramproject.slice -p MemoryCurrent -p MemoryMax -p CPUQuotaPerSecUSec
# 从统一入口启动/停止本项目；不停止其他项目的Docker
/mnt/sda/engramproject/platform/start.sh
/mnt/sda/engramproject/platform/stop.sh
```

systemd用户单元保留在用户配置目录作为系统启动指针；实际运行Compose、daemon配置和FRP状态位于机械盘。Docker data-root仍在SSD。启动前必须确认/mnt/sda和/mnt/sdh已挂载，挂载丢失不得向同名系统盘目录继续写入。

## 镜像、代码与数据分别更新

- 网页文案/样式：构建网页、验证后发布网页代码，仅重建受影响web容器以更新绑定。复用已有镜像，数据库与附件不动。
- 后端逻辑：新代码目录加备份，重建API和受影响worker，不重建数据库或重新导入数据。
- 依赖或运行环境：才准备/加载匹配的新镜像，记录实际镜像ID；普通更新禁止自动拉取或重建镜像。
- schema变更：备份并验证数据库dump后单独执行迁移；仅切回旧代码不能撤销数据库迁移。
- 本次存储重排需要一次停止并重建服务挂载；日常小改动不重复执行存储迁移。

发布前检查工作区与提交、磁盘和挂载、正在执行任务、镜像ID、代码校验及当前Compose；不能以打包成功替代上线验证。私有Compose、.env、FRP认证来源以及备份不入Git，权限0600/0700，不输出密钥。保留现有工作区模型、账号、签名反馈来源和采集电脑身份。

## 备份、回退与验收

迁移先预复制，停止本项目写入后再同步并逐文件校验。数据库仍使用原SSD卷，切换前生成pg_dump并以pg_restore --list核验；旧文件目录保留，不做自动清理。切换失败时停止新实例，恢复旧Compose与systemd指针、启动旧实例；若已经产生新附件或写入，先保留并核对新增数据，不盲目用旧备份覆盖。

验收包含公网页面/API、登录、既有用户/项目/缺陷/附件数量、附件实际读取校验、诊断worker与4并发队列、195反馈与远程卡片在线、原模型配置保留、无额外公开数据库/内部服务端口，以及实际挂载和cgroup限制。保持原公网URL和DAQ配置，不因代码或IP显示变化重新登记采集电脑。

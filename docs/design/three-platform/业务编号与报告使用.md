# 业务编号与诊断报告

## 编号

| 内容 | 示例 | 说明 |
|---|---|---|
| 开发任务 | DEMO-T-8 | 原工作项序号保留 |
| 需求 | DEMO-R-2 | 原独立需求序号保留 |
| 缺陷 | DEMO-D-8 | DAQ或网页创建采用同一分配器 |
| 测试用例 | DEMO-C-1 | 修改产生用例版本，编号不变 |
| 用例集 | DEMO-S-1 | 不使用用例内容版本充当集合编号 |
| 测试计划 | DEMO-P-1 | 回归计划也用计划编号，轮次单独展示 |
| 执行记录 | DEMO-E-1 | 每次实际执行独立记录 |
| 技术方案 | DEMO-SOL-1 | 审核版本单独保存 |
| 版本迭代 | DEMO-V-1 | 业务编号与软件版本号分开 |
| 发布检查 | DEMO-REL-1 | 软件版本与准入记录分开 |
| 知识 | DEMO-K-1 | 发布版本与知识引用版本另行保留 |
| 问题包 | DEMO-PKG-1 | 保存诊断附件清单 |
| 测试报告 | DEMO-REP-1 | 保存生成快照 |
| 环境设备／采集资源 | DEMO-RES-1／DEMO-AG-1 | 记录不等于控制设备 |

DEMO为项目标识示例，新项目使用自身标识。后台自动分配，用户及DAQ均不填写序号。业务编号固定保存；修改标题、状态、归档不改号。复制为新记录则重新分配，历史删除也不复用编号。项目改标识后原记录编号保留，新记录使用新标识。内部UUID和外部数据平台ID均保留，不替换关联键。

DAQ上报返回issueCode为平台缺陷编号，并返回nativeUrl进入具体缺陷。同一幂等键重试返回同一记录编号；不同问题可建立不同缺陷并继续引用相同Session。

入口：模块内“筛选→编号”可精确筛选；关键词可搜完整编号或标题；顶部搜索可用完整业务编号定位已授权的主要记录。无权限、已删除或已归档内容不通过顶部编号查询泄漏。编辑器、版本和知识引用仍保留各自版本信息，不能把v1～v4看成不同缺陷。

参考：Plane v1.4.3原始Issue使用项目内序号与IssueSequence，事务锁后分配；禅道main的testcase配置直接支持id搜索，testtask默认表头含id。新版借鉴稳定ID与可搜索原则，并加入类型标识适配统一平台。

## 诊断报告

“当前报告”在主区域，“历史报告（数量）”默认折叠。最新重试失败或排队时，同批材料可继续看最近成功模型报告；材料变化后不自动沿用旧结论。模型失败保留规则检查，显示“仅规则结果”，不显示为模型诊断成功。

报告页显示读取字节数、文件大小（新生成记录）、是否部分读取／预览摘录及模型摘要限长。旧报告不回写伪造新的读取范围元数据。

诊断记录不是缺陷处理状态；有报告不代表已修复、回归通过或已关闭。

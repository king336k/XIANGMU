# 公网与内网部署验证

2026/11/10。本轮验证使用本机独立Docker网络和业务副本，没有部署公网，没有修改宿主机路由、防火墙、DNS或代理，也没有改现有DAQ、数据平台、157或195。

## 结论

**仅DAQ电脑能上网可以实现，但当前默认直连配置不够，需增加受限的双向连接通道。** 数据平台不必能访问普通互联网；只要能通过内网访问DAQ上的转发入口。公网项目平台访问数据平台的必要回读，也经DAQ主动建立的通道返回。

| 场景 | 配置 | 本轮结果 |
| --- | --- | --- |
| 项目平台、数据平台同一服务器 | 分容器或独立进程，在私有服务网络互访；不用另一容器的localhost | 关闭frp后，Java签名上报重试、来源账号登录、项目目录同步通过 |
| 两台内网服务器 | 双方内网服务地址互访 | 同样在frp关闭后实际HTTP通过 |
| 公网项目平台、内网数据平台，仅DAQ可外连 | DAQ双网可达+frp STCP私有通道+固定路径代理 | 签名上报、账号登录、目录同步、附件、回归及故障恢复通过 |

普通内网测试保持直连；frp单独启用。当前数据平台业务路径仍是DAQ→数据平台Bridge→项目平台；签名密钥留在数据平台，项目平台继续核验来源身份、权限、任务和Session。

## 选型

选用[fatedier/frp](https://github.com/fatedier/frp) **v0.72.0** 做实际验证。2026/11/10官方GitHub API核实110,492星，Apache‑2.0。它提供STCP私有访问、TLS和重连，满足这一固定双向HTTP需求；rathole是更小的备选，官方14,433星/Apache‑2.0，但本轮没有安装或测试它。OpenSSH反向隧道也能承担转发，本轮未将其作为最终业务通道。

官方发布包14,564,595字节，SHA256：`daf719b32ca2778770bb92955e231a07414d754378b9af328aa2642862479804`，与GitHub release digest一致。直接下载超时后通过GitHub官方API下载并验证，没有使用第三方镜像包。

## 网络隔离

- 模拟公网、现场LAN、云端私有服务网是三个`--internal` Docker网络。
- 数据平台只加入LAN，没有默认路由；DAQ同时加入模拟公网和LAN。
- 公网平台不能直接访问数据平台LAN地址；数据平台不能直接访问公网API。两项负向TCP检查均被阻断。
- frps只提供控制通道；STCP没有公开业务remotePort。数据平台回读端口仅绑定云端私有服务接口，外部测试节点访问被阻断。
- 新容器均带专属标签，无宿主机端口映射、无host网络。口令和隧道密钥只经进程内存或容器tmpfs处理；数据库副本也存tmpfs。原库仅只读导出，导出字节在内存直接导入测试库，没有落盘副本。
- 未更改电脑系统配置；最终清理与基线核对结果保存在本轮证据目录。

## 实际业务测试

| 检查 | 结果 |
| --- | --- |
| DAQ使用来源账号登录，数据平台签名解析项目 | 200，映射NET155隔离项目 |
| 上报、同请求重试 | NET155-D-1，始终同ID与编号 |
| 10并发同一请求 | 全部返回同一ID，无重复报告记录 |
| 服务已接收后模拟客户端响应断开 | 相同请求重试200，保持原编号 |
| 9MiB+27B不可压缩附件 | 3分段；首分段重复上传；总9,437,211字节下载SHA一致 |
| DAQ通道停止 | 上报502；恢复200，原编号保留 |
| 公网frps重启 | 客户端重新连接，上报恢复200 |
| 来源账号在项目平台登录及持续身份核验 | 200，经理岗位正确；普通本地账号仍可独立登录 |
| 项目与任务目录同步 | 200，仅当前映射项目写入快照 |
| 新Session证据、测试执行、提交 | 201/201/200；来源数据为明确隔离fixture |
| 最终确认时通道断开 | 503，拒绝最终确认；恢复后重新权威回读200，计划完成、缺陷关闭 |
| 任意创建用户、管理环境、错误方法 | 私有路径代理403 |
| 错误隧道token、未授权外部节点 | 不能获取数据平台业务响应 |
| 非TLS连接 | 不能通过强制TLS控制通道访问业务 |

文件测试最初把正确的HTTP206分段下载误判为失败，已修测试脚本断言，产品未放宽。回归种子的SQL `NOW()`为UTC无时区，而来源配置为中国标准时间，初次被正确拒绝；只改隔离数据的采集时间，保留产品新数据边界。首轮数据库克隆启动时认证未就绪，已在独立副本恢复；没有修改源数据库。

## 使用方式与边界

配置模板见[deploy/network/README.md](../../../deploy/network/README.md)，包括frps、云端frpc、DAQ端frpc和固定路径Nginx。三个frp模板已用官方v0.72.0 `verify`检查，路径代理通过Nginx语法和真实允许／拒绝请求验证。模板不会自动安装或修改任何电脑。

DAQ电脑必须持续开机、可访问内网数据平台，也能访问公网frps；仅“能打开网页”不代表控制端口一定可用，需按目标网络策略验收。电脑关机、休眠或换网时通道暂不可用，需恢复后重试；无人值守建议采用内网常开网关。

本轮是实际应用代码和真实网络传输的**本机隔离模拟**，不是正式公网线路、运营商网络、目标服务器TLS证书或机器人现场验收。没有重复调用模型；诊断模型能力沿用先前已验链路，不能称本轮跨公网模型完整效果通过。没有上传MCAP、视频或完整录制数据。

本轮配置不自动开放公网入口。正式上线仍须目标HTTPS、可信Origin、安全Cookie、域名与访问策略、WebSocket、附件下载和负载验收；域名/IP按用户安排暂不选定。

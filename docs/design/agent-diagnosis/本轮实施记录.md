# 本轮实施与后续边界

日期：2026/11/09。代码统一位于本仓库；157及原数据平台保持只读。

## 已实现的第一段闭环

- 每条 DAQ 新上报创建缺陷后自动进入诊断队列，不要求采集员手动点击。
- 同一问题包所有文件通过校验后，基于新材料生成新报告版本；重试不重复建单，不覆盖历史报告。
- 材料读取器支持独立文本与安全 ZIP 内文本，记录实际读取文件、摘要和截断信息。
- 迁入参考平台12条 YAML 规则，并保留原有超时、连接失败与异常扫描。来源摘要命中标记“需结合现场日志核实”，不当作已确认根因。
- 引入 PydanticAI 2.66.0，独立 Python 环境与独立诊断 worker，不替换原后台的模型 SDK。
- 两个受控工具：读取本任务授权材料、检索本任务已发布知识。没有任意磁盘、命令或机器人控制工具。
- 模型报告校验结构、来源引用和疑似敏感内容；模型失败保留规则结果。
- 缺陷详情按概况、诊断、处理方案、回归测试和操作记录分区；自动上报的记录默认进入诊断。
- 最新报告直接展示，历史报告折叠；可查看已读取日志片段和下载原包。

## 当前并发和时限

独立诊断队列 diagnostics，初始1个 worker、每个并行2个任务、预取1。部署配置：
DIAGNOSTIC_WORKERS、DIAGNOSTIC_CONCURRENCY、BACKGROUND_CONCURRENCY。

排队与执行分开计时。任务排队最多保留15分钟，过久显示“排队等待过久”，支持重试；
真正执行后 Celery 软上限160秒、硬上限180秒。页面兜底核对已执行超过190秒的任务，避免长时间停留在“分析中”。
Agent 取证阶段最多85秒；达到取证预算后停止查询，最多再用30秒根据已有材料生成报告。整体目标上限120秒、外层子进程125秒；总请求最多6次、取证工具最多10次。按用户要求优先充分分析，不要求几十秒内出结论。
这些是初始工程边界，不是准确率或全量负载的性能承诺。

已观察到旧3条规则任务执行4–8毫秒；真实模型合成样例约20.5秒；实际本机队列合成上报v1约25秒、补ZIP后v2约33秒。
尚未用几十名采集员真实同时上报测试，扩容前要测模型限流和服务器资源。

## 尚不能宣称完成

- 最新 DAQ Git 分支完整部署、与新平台账号及所有页面的全链路回归。
- 157数据库知识正文、历史报告及附件的完整数据迁移；目前取得的是源码与规则。
- 设备手册PDF/Word自动解析。当前知识导入支持2MB内UTF-8 Markdown、TXT或JSON，位于“项目 → 文档与知识 → 知识 → 导入文档”，确认后进入知识维护草稿。
- 数据回归经理验收后已有自动知识草稿，但完整根因、步骤、审核和回归证据溯源仍需扩充；并非所有普通缺陷关闭都会自动生成完整知识。
- 知识重开自动失效、版本适用性、语义召回质量和历史失败经验的完整闭环。
- 针对真实设备问题的准确率提升。此前的时间减少20%–30%、根因命中提高10–20个百分点仅为待验证目标。
- 直接读取采集机部署源码或机器人状态；需要另接白名单只读诊断接口。
- 真实机器人、外部升级目录与既有服务配置及生产部署切换等历史待验项。

交互方案预览采用示例数据，正式缺陷页的已实现内容以实际运行和验收记录为准。

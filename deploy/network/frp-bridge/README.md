# frp独立连接包

用于公网项目平台与内网数据平台之间的专用访问。默认只检查配置，不修改电脑路由、防火墙、DNS、代理，也不自动注册系统服务。只有显式`--run`才启动当前角色的前台进程，Ctrl+C停止本次启动的进程。

- 公网端：frps服务端 + cloud私有访问端，各自独立进程或容器；云端访客6324只在私有服务网络可见。
- 采集电脑：daq客户端 + 模板中的固定路径Nginx代理，须能访问数据平台LAN地址。
- 数据平台不用安装frp；首次将Bridge上游改为DAQ私网18000入口。项目平台来源回读地址改为云端私有访客地址。修改必须在独立部署配置中进行，不能覆盖既有测试／内网配置。
- 采集员在DAQ照常上报、补充和查看结果，不需要每次操作frp；后台常驻方式由部署人员在目标电脑确认后配置。
- 同机或普通内网部署直接连接，不使用此包。

## 准备

离线代码包的`bin/`包含已核验frp v0.72.0 Linux amd64官方二进制与LICENSE。其他系统架构请从官方release取得对应版本并校验，不混用二进制。

将实际配置从部署系统环境注入。`FRP_AUTH_TOKEN`、`FRP_HUB_SECRET`、`FRP_AUTHORITY_SECRET`须使用不同的随机值；不要将其写进README、Git、命令行或聊天。证书路径由`FRP_CERT_FILE`、`FRP_KEY_FILE`、`FRP_CA_FILE`指定，TLS服务器名由`FRP_TLS_SERVER_NAME`指定。

非秘密字段：`FRP_SERVER_ADDR`、`HUB_INTERNAL_HOST`、`CLOUD_PRIVATE_BIND_IP`、`DAQ_LAN_IP`。公网端和DAQ端使用同一控制服务器与相应业务密钥。

先检查：

```bash
python3 bridge.py server
python3 bridge.py cloud
python3 bridge.py daq
```

只在对应主机运行对应角色的检查。检查通过后，明确加`--run`启动前台服务。不会下载软件、安装服务或自动开放端口。停止用Ctrl+C；无需执行全局进程清理命令。

Nginx模板中的`DATA_PLATFORM_LAN_HOST`只替换为指定源站，`nginx -t`检查通过后由目标部署管理工具启动。不要使用动态上游、通配路径代理或把6324映射公网。DAQ入口18000仅允许数据平台地址访问，目标防火墙调整需管理员明确操作；此包不代改。

完整连接方向、三种模式、断线行为和隔离证据见上级README及`公网与内网部署验证.md`。此包已在本机隔离网络验证，不等于已部署到采集电脑或正式公网。

## 可选随系统启动

`systemd/engram-frp@.service.example`供目标主机管理员审查后安装，分别使用server、cloud、daq实例。需先创建专用低权限用户与0600环境配置，证书只读。此包不执行用户创建、服务安装、enable、开放防火墙等系统操作。DAQ电脑上的固定路径Nginx需由部署管理员同样设为后台服务。

## 多台采集电脑

一个数据平台默认指定一台持续在线的采集电脑作为通道网关，其余采集电脑仍正常访问同一数据平台，无需每台安装frp或修改DAQ操作。此包的固定代理名用于单网关，不能把相同配置同时装到多台电脑争用。若要双机接替或按多个数据平台隔离，应独立规划通道编号、源站映射和切换策略后再验收。网关电脑离线会暂时影响跨公网业务，普通内网采集本身不应依赖公网通道。

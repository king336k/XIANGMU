# 项目平台与内网数据平台的连接

普通内网部署使用直连。只有项目平台在公网且数据平台无外网时，才启用下面的可选通道。

| 部署 | 数据平台 → 项目平台 | 项目平台 → 数据平台 | DAQ需要公网 |
| --- | --- | --- | --- |
| 同一服务器、分容器 | 专用Docker网络中项目API地址 | 专用网络中数据API地址 | 否 |
| 不同内网服务器 | 项目平台内网地址 | 数据平台内网地址 | 否 |
| 公网项目平台，只有DAQ联网 | 数据平台Bridge → DAQ内网监听 → 私有通道 → 项目API | 项目API → 私有访客监听 → DAQ路径过滤 → 数据API | 是 |

同一服务器不能把另一个容器当作`localhost`。使用专用容器网络和服务名；账号来源页面若使用HTTP，需要明确私网IP及“允许私网HTTP”，不放宽现有校验。用户浏览器入口与后台源站地址分别配置。

## 仅DAQ联网：frp私有访问

使用官方 **frp v0.72.0** 的STCP模式。官方仓库：https://github.com/fatedier/frp 。STCP没有业务remotePort，未持有访客密钥的普通公网连接无法直接访问内网服务。

- 公网端运行frps及一个frpc；DAQ运行另一个frpc及固定路径Nginx代理。无需在数据平台服务器安装frp，也不改其路由、DNS或系统代理。
- DAQ同时能访问数据平台内网地址和公网frps控制端口。数据平台只需能访问DAQ内网地址的18000端口。
- 公网API和数据平台回读访客监听放在专用私有容器网络，6324不发布到宿主机。`CLOUD_PRIVATE_BIND_IP`必须为该专用网络的私网地址；不能填公网地址或0.0.0.0。
- 数据平台独立配置中的`ISSUE_BRIDGE_UPSTREAM`指向`http://DAQ_LAN_IP:18000`，`ISSUE_BRIDGE_ALLOWED_UPSTREAM_HOSTS`仅允许该DAQ地址。保留原签名密钥、鉴权和幂等规则；来源凭据不能放进DAQ前端。
- 项目平台“平台集成 → 服务器连接配置”的数据源地址指向公网侧私有访客IP的6324端口。保留原`portal_url`供内网人员访问数据平台网页；公网人员未接入内网时该网页链接不保证可达。
- frps、两端frpc使用不同用途的随机密钥，通过运行环境/secret文件注入，不写入Git；TLS校验证书链及服务器名，禁止关闭校验。环境模板字段见三个`.toml.example`。
- `authority-filter.nginx.conf.example`只允许登录、当前身份和必要只读核验/目录接口，拒绝用户创建、任意路径及不允许的方法。后台仍检查Bearer/HMAC权限，路径过滤不能代替业务鉴权。
- 采集电脑关机、休眠、换网络或失联时，这条通道会中断；frpc会尝试重连，业务失败保留重试，最终回归不能跳过权威回读。若需无人值守持续可用，宜用内网常开网关承担同样职责。

此目录是可审查的部署模板，不会自动安装、开端口或修改电脑配置。部署公网前还需设置HTTPS入口、可信Origin、安全Cookie、允许域名、附件下载地址及WebSocket，并在目标环境验收。仅内网测试无需启用frp。

## 本机隔离证据

测试使用两个隔离内外网、一个私有服务网络和独立业务数据库副本，无宿主机端口。实际DAQ端HTTP经Java可信Bridge → frp → Django API → frp回读。包括断线、接收后丢响应重试、9MiB不可压缩附件、10并发同请求和回归最终断线拒绝关闭。报告见 `docs/design/three-platform/公网与内网部署验证.md`。

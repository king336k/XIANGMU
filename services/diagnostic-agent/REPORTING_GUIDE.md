# 诊断与现场处理报告规范

报告先回答现场人员的四个问题：发生了什么、原因是什么、处理了什么、怎样确认。长依据放详情，真实执行位置和前后值保留在变化明细。报告整理不能改变历史事实、把推测升级为结论或扩大验证范围。

## 普通诊断主摘要

新生成的 `answer` 默认仅三短段，各一句：

```text
**故障**：复位目标超限，日志说明了直接失败环节。
**已处理**：按批准计划将初值3.3065改回0.3065，配置复查通过。
**待验证**：现场人员安全执行复位，完成且无同类错误才确认业务恢复。
```

示例只说明写法，不是预置现场结论；数值与操作仅能来自本任务实际证据。

以100至180个中文字符为目标；当前生产生成 `ActionableReport.answer` 最长220字符。每段一句，简单问题可省略无内容的段落，不再为了填满四块重复。旧四段和旧长报告仍可读取，不截断或重写历史事实。

- **故障**：先说原失败操作的直接环节；原因不明只说一次，并写最小下一检查。
- **已处理**：只写真实修改及关键前后值，或本轮实际检查结果；尚未执行的建议不能写成已完成。
- **待验证**：一个具体动作和通过标准；配置通过不能替代原运动、复位或采集业务验收。

维护更新导致的停机或暂未连接，不替代原缺陷作为主句，除非原问题就是未连接。纯复测可简述当前检查通过、必要历史处理、待业务验收。

证据与权限规则用于内部判断，不是公开免责声明清单。正文和详细依据不写UUID、哈希值、内部平台引用编号、工具ID或JSON字段解释，不逐项反证VR、Session、收据和未活动模块。完整ID保留在结构化引用与追踪中；可读来源标题、实际文件名/函数和关键原始日志是专业内容，允许使用。真实长路径、行号、备份及前后差异由变化明细保留。

`suggested_actions` 和 `verification_steps` 各1至3项：前者是具体处理动作，后者是结果判定标准，不将同一句建议重复两遍。证据不足时，最小只读补证及相应判定标准有效；不编造修复结果。

## 现场 Agent 的兼容结构

继续使用原有 `summary/root_cause/actions/verification/solution/repair_locations`，由展示层对应问题、原因、处理、验证；不改变历史记录的字段或结果。

- `summary` 最多120个中文字符，先写当前状态。
- `root_cause` 最多2句，区分证实与推测；必要时一句区分上报时故障与当前状态。
- `actions` 仅实际处理，最多4条；`verification` 仅真实检查，最多4条。
- `solution` 正常时最多2句，未恢复时最多4项明确下一步。
- 实际路径、可靠行号、配置键/函数、前后值及备份由 `repair_locations` 和变化明细完整呈现。摘要不重复复制，也不能声称真实回执中已有的位置不存在。

独立模型收尾阶段与证据工具阶段使用同一事实边界。模型意见、依赖导入、Ping、标准 ROS topic、配置检查或隔离代码单测，都不能替代原故障对应的业务验收。

新现场报告另提供 `brief_report`，按“故障／已处理／待验证”各一句生成，最长220字符。公开回复优先使用它，旧报告缺少该字段时继续读取原字段。“配置已修复，待业务验证”等状态也使用同一结构，不回退为原始文本。详细依据标题独占一行，供平台和DAQ统一折叠。

## 大日志与部分材料

附件完整性校验与正文扫描覆盖分别记录。SHA、尺寸、ZIP CRC或路径校验失败时不调用模型；完整性通过但扫描未结束时，可以分析实际读取的片段，同时明确未读范围。未读条目的预算提示不作为日志原文。

部分材料分析不自动修改严重程度或模块分派，不认定全部正常或已修复。主分析、超时收尾及直接模型接口使用相同的范围约束；有可读日志但图片未读取时也按部分覆盖处理。

## 详细依据

`evidence_details` 默认空，只保留2至4条最关键的原始日志或源码依据。当前普通生产生成最长800字符；基础历史反序列化仍兼容旧10000字符字段，现场报告也以800字符以内为目标。完整证据已有附件与原日志，不重新扩写全部取证过程或重复主段。详情不能制造新的执行事实。

可以保留实际来源、事件时间、部署版本、文件/函数、配置项、命令退出码、原始错误、备份、前后差异、未决假设与必要限制。知识和文件引用仍必须属于本任务清单并列入结构化最终引用，正文用可读来源标题；详情不是绕过引用或凭据过滤的通道。实际代码位置必须有已读取来源或回执支持；无可靠行号时给配置键或函数，不能猜。

代码建议还应说明是否需构建部署；系统故障需明确服务/进程与失败证据，不能把重启当通用根因；硬件问题明确远程证据可支持的范围和现场检查对象。正确配置值必须有设备认可来源或独立批准计划，release默认和旧备份仅是候选。

## 文风与证据合同

用具体对象和动词，不写开场套话、反复总结、泛泛“联系相关人员”或重复免责声明。材料已经支持的事实直接摘出，不要求人员重读整份日志。当前证据、历史材料和待执行建议必须分开；历史成功不能证明当前恢复。

PLATFORM-RECEIPT只证明本平台收到对应材料；PLATFORM-VERIFICATION只证明记录所列回归范围；PLATFORM-FIELD-CHECK代表后来实际现场处理及复测，必须与上报时附件按时间区分。知识库与 REVIEW 历史反馈是参考，不是本次执行回执。源码引用必须匹配实际仓库/子仓库版本。

报告由主 Agent 依证据生成，展示层只整理结构与折叠详情，不另起一个拥有现场权限的改写 Agent。模型密钥、口令、token、私钥或无关私人内容不得进入报告。所有现有引用、严重程度逐字证据、自评依据与可执行步骤校验保持有效。

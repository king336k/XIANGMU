# 诊断与现场处理报告规范

报告先回答现场人员的四个问题：发生了什么、原因是什么、处理了什么、怎样确认。长依据放详情，真实执行位置和前后值保留在变化明细。报告整理不能改变历史事实、把推测升级为结论或扩大验证范围。

## 普通诊断主摘要

新生成的 `answer` 默认采用四个短段，标签与顺序固定：

```text
**问题**：上报时复位失败；当前配置复查已通过，原复位操作仍待验收。
**原因**：原始日志显示复位目标超出关节范围。现场回执确认对应初值曾被改动。
**处理**：已按批准计划更正该初值并保留备份。
**验证**：配置语义检查通过；获授权人员仍需执行原复位操作，确认成功且无同类错误。
```

示例说明写法，不是预置现场结论；只有本任务实际证据支持时才可使用对应事实。

每段1至2句，四段合计以250至400个中文字符以内为目标。简单问题可以更短，不为凑字数重复，也不按字符数机械截断关键事实。默认主摘要不复制标题、UUID、长路径、hash、版本清单或内部工具名。

- **问题**先说当前状态；历史故障与当前处理有差别时，用一句说明时间关系。
- **原因**直接区分“已确认”与“可能、待验证”；缺证据时说具体缺项，不编造硬件损坏或软件根因。
- **处理**写真实执行；没有修改就说本轮仅检查。尚未执行的建议使用“待执行、需授权”等准确词语。
- **验证**写实际检查与通过标准，限制结论范围。配置通过不证明运动、复位或采集恢复；原业务验收确实缺失时才简明指出。

VR未活动、Session未关联、材料/版本收据、模拟标记和其他边界，不是每份报告必填的免责声明。只有直接影响本缺陷因果判断或可能导致误认恢复时才进入主摘要；其余必要说明保留到详细依据。不要为了“简洁”忽略已给原始错误、实际修改回执或有效复测。

`suggested_actions` 与 `verification_steps` 各保留3至4项以内的具体步骤：对象、动作、适用前提或通过标准。生产生成合同仍要求两者非空；证据不足时，最小只读补证及对应判定标准也可以构成有效步骤。

## 现场 Agent 的兼容结构

继续使用原有 `summary/root_cause/actions/verification/solution/repair_locations`，由展示层对应问题、原因、处理、验证；不改变历史记录的字段或结果。

- `summary` 最多120个中文字符，先写当前状态。
- `root_cause` 最多2句，区分证实与推测；必要时一句区分上报时故障与当前状态。
- `actions` 仅实际处理，最多4条；`verification` 仅真实检查，最多4条。
- `solution` 正常时最多2句，未恢复时最多4项明确下一步。
- 实际路径、可靠行号、配置键/函数、前后值及备份由 `repair_locations` 和变化明细完整呈现。摘要不重复复制，也不能声称真实回执中已有的位置不存在。

独立模型收尾阶段与证据工具阶段使用同一事实边界。模型意见、依赖导入、Ping、标准 ROS topic、配置检查或隔离代码单测，都不能替代原故障对应的业务验收。

## 详细依据

普通诊断和现场 Agent 增加可选 `evidence_details` 字符串，默认空、最多10000字符；旧记录缺字段仍有效。它供详情折叠展示，不通过修改旧报告制造新的执行事实。

可以保留实际来源、事件时间、部署版本、文件/函数、配置项、命令退出码、原始错误、备份、前后差异、未决假设与必要限制。知识和文件引用仍必须属于本任务清单且列入最终引用，详情不是绕过引用或凭据过滤的通道。实际代码位置必须有已读取来源或回执支持；无可靠行号时给配置键或函数，不能猜。

代码建议还应说明是否需构建部署；系统故障需明确服务/进程与失败证据，不能把重启当通用根因；硬件问题明确远程证据可支持的范围和现场检查对象。正确配置值必须有设备认可来源或独立批准计划，release默认和旧备份仅是候选。

## 文风与证据合同

用具体对象和动词，不写开场套话、反复总结、泛泛“联系相关人员”或重复免责声明。材料已经支持的事实直接摘出，不要求人员重读整份日志。当前证据、历史材料和待执行建议必须分开；历史成功不能证明当前恢复。

PLATFORM-RECEIPT只证明本平台收到对应材料；PLATFORM-VERIFICATION只证明记录所列回归范围；PLATFORM-FIELD-CHECK代表后来实际现场处理及复测，必须与上报时附件按时间区分。知识库与 REVIEW 历史反馈是参考，不是本次执行回执。源码引用必须匹配实际仓库/子仓库版本。

报告由主 Agent 依证据生成，展示层只整理结构与折叠详情，不另起一个拥有现场权限的改写 Agent。模型密钥、口令、token、私钥或无关私人内容不得进入报告。所有现有引用、严重程度逐字证据、自评依据与可执行步骤校验保持有效。
